# 对标锁定与拆解手册（Benchmark Playbook）

## 一、关键词扫描

1. 从账号定位提取 **2-4个细分关键词**。原则：语义细分优先于大类词。
   - 差："美食"、"文化"（大类词，结果泛化）
   - 好："祭祖流程"、"紫微斗数"、"节气美食"（细分词，结果精准）
2. 在目标平台搜索（API 或网页搜索均可），按互动量排序，抓取前 20-40 条结果。
3. 每条结果需要的字段：作者、标题、发布时间、播放或曝光、点赞、评论、收藏、转发/弹幕（平台有啥抓啥）。
4. 关键词搜不出内容时自动扩展：生成10个2-6字相近词重试。
5. 换词再扫一轮（共2-3轮），扩大候选池。

## 二、按作者聚合（信号判读）

把搜索结果按作者分组统计，核心指标与判读：

| 指标 | 计算 | 信号含义 | 学习对象类型 |
|------|------|---------|-------------|
| 上榜条数 | 该作者出现次数 | 输出稳定性 | 产能/纪律型 |
| 均赞 | 总赞/条数 | 单条质量 | 内容质量型 |
| **藏赞比** | 收藏/点赞 | >1=收藏驱动（实用干货） | 干货清单型 |
| **评赞比** | 评论/点赞 | 高=互动驱动（对号入座/争议） | 评论区运营型 |
| 弹幕/转发 | 平台特有 | 社交传播驱动 | 社区互动型 |

**选对标的策略**：2-3个对标尽量覆盖不同信号类型（如一个内容质量型+一个干货收藏型+一个互动运营型），分别学不同的东西。藏赞比>1 或 评赞比 显著高于均值的账号优先入选。

## 三、聚合脚本用法

`scripts/aggregate_benchmarks.py`：输入一个或多个搜索结果 JSON 文件，输出作者排行榜。

```bash
python scripts/aggregate_benchmarks.py result1.json result2.json [--top 25] [--out out.txt]
```

- 输入 JSON 格式：`{"articles": [{"author": "...", "title": "...", "like_count": 0, "collect_count": 0, "comment_count": 0, "share_count": 0, "play_count": 0, "danmaku_count": 0}]}`（缺的字段自动按0处理）
- 自动兼容 UTF-8 / UTF-8-BOM / UTF-16 编码
- 输出：按总赞排序的作者榜（条数/总赞/均赞/藏赞比/评赞比/代表作标题）

无脚本执行环境时，用同样指标做人工聚合（电子表格即可）。

## 四、六项对标档案（每个对标必须集齐）

1. **内容定位**：一句话说清"给谁提供什么"（例："给广东本地人讲身边的民俗"）
2. **选题方向**：列出其 3 个核心内容引擎/系列（固定栏目是涨粉架构的核心）
3. **发布节奏**：更新频率 + 具体时段（连看最近 5-10 条的发布时间，纪律性是可复制的）
4. **封面标题策略**：拆出可复用的标题公式（前缀/句式/数字/悬念类型）
5. **互动数据表现**：爆款率、单条中位数、评论区生态（评论内容本身是否成为素材）
6. **变现方式**：广告/带货/付费内容/私域咨询——决定该对标对你的优先级

## 五、头部账号数据补全技巧

实时搜索 API/网页搜索常只覆盖近期内容，头部老号可能搜不到。补全路径：

1. 公开资料检索：搜"账号名 + 粉丝/UID/账号拆解"，百科/拆解文章常含粉丝量、代表作、合集结构
2. UID 反查：拿到主页链接中的 UID 后，用平台公开的作品列表接口/工具拉取作品数据（播放/互动/发布时间）
3. 实在抓不到的维度（如后台完播率）：标注"公开数据不可得"，用可见指标近似评估，不编造数据

## 六、对标拆解的产出标准

每个对标输出一节，结尾必须回答三个问题：
- 他的哪个做法是我**立刻能抄**的？（发布时段/标题公式/栏目结构）
- 他的哪个做法是我**暂时学不了**的？（资源/人设/团队差距）
- 他**没做但我能做**的差异化切口是什么？（这是机会点的重要来源）
